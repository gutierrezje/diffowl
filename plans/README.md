## Commit and review cadence

For each plan:

1. Keep the implementation to the listed scope and make tests pass.
2. Run `pnpm run test`, `pnpm run lint`, `pnpm run format:check`, and
   `pnpm run build`.
3. Stage only the implementation files and run `diffowl review --staged`.
4. Treat generated findings as candidates. Investigate them according to
   `skills/diffowl-resolve/SKILL.md`, fix confirmed issues, and re-run the
   review when code changes.
5. Commit one green logical unit with the conventional message named in the
   plan. Do not commit `.diffowl/` workflow records unless explicitly asked.

## Findings considered and rejected

- Replace the hand-written diff parser wholesale: not justified; the confirmed
  defect has a narrow shared-decoder fix and existing parser contracts are
  extensive.
- Upgrade dependencies as an audit priority: `pnpm audit --prod` reported no
  known vulnerabilities; available updates are minor except Commander and do
  not currently justify migration risk.
- Treat the npm pack failure as a product bug: packaging reached the build
  successfully and then hit a local root-owned npm cache permission problem.
- Change SIGTSTP behavior as a correctness fix: current Ctrl+Z cancellation is
  intentional in code and history; the prior report did not establish a
  supported suspend/resume contract.
- Report the hook worker's nonzero signal exit as blocking `git commit`: the
  worker is detached after the post-commit command returns, so that impact was
  misattributed.
- Refactor `src/cli.ts` or `src/opencode/client.ts` based on size alone: no
  standalone decomposition had enough concrete payoff to outrank the behavioral
  findings.
- Fix minor timer cleanup in health checks or reconciliation races: bounded
  timers have low impact and are not worth extra lifecycle complexity now.
- Tighten `selectReviewReportPath` input from `parseInt` to digits-only: valid
  users select from a prompt and the accidental `1abc` acceptance has negligible
  product impact.
- Make report writes atomic: reports are local append-only workflow artifacts,
  writes are small, and there is no evidence of partial files in practice.
- Add changed AST line mapping for arbitrary octopus merge shapes beyond the
  real two-parent case: defer until a supported use case demonstrates the
  complexity is justified.
- Bundle TypeScript as a runtime dependency: TypeScript repositories normally
  provide their compiler, and the current best-effort fallback already emits a
  diagnostic when unavailable.
- Add broad unit tests for `src/cli.ts` solely to improve coverage: prefer
  targeted extraction only when a behavioral plan such as 012 or 013 requires
  it.
