# DiffOwl 0.3 Dogfood Checklist

Local release gate for durable findings. Run deterministic CI with `pnpm run test` and `pnpm run lint`; use this checklist once on a fresh generated repo before calling 0.3 done.

## Setup

From the DiffOwl repository:

```bash
pnpm dogfood:0.3
```

The script builds `dist/cli.js`, creates a temporary Git repo, stages intentional dogfood bugs, and prints the repo path plus commands. It does not modify the DiffOwl repository except through `pnpm run build`.

Optional model override:

```bash
DIFFOWL_DOGFOOD_MODEL=provider/model pnpm dogfood:0.3
```

## Manual Scenarios

Use the CLI path printed by the script (`node <diffowl-root>/dist/cli.js`). All commands run from the generated temp repo unless noted.

### 1. Deduplication

```bash
diffowl review --staged --verbose
diffowl review --staged --verbose
diffowl findings
```

**Pass when:**

- One repeated-issue row in `diffowl findings`
- `Seen` shows `2x` (or higher if you rerun)
- Latest report heading includes one `fnd_*` id with `existing` on the second review

### 2. Dismissal suppression

```bash
diffowl findings dismiss <repeated_fnd_id> --reason "Dogfood dismissal."
diffowl review --staged --verbose
diffowl findings
```

**Pass when:**

- Dismissed finding is absent from `diffowl findings`
- Verbose review diagnostics mention suppressed dismissed count
- Actionable findings exclude the dismissed issue

### 3. Fixed then regressed

```bash
diffowl findings fix <regression_fnd_id> --note "Dogfood fix." --verified-by "git diff --check" --actor agent
diffowl review --staged --verbose
diffowl findings
```

**Pass when:**

- Fixed finding reappears in backlog as `regressed`
- Verbose report labels it `regressed`
- `diffowl findings show <id>` includes a `regressed` event

### 4. Absence does not auto-fix

Commit the staged bug fixtures so later reviews are not polluted by `src/repeated.ts` and `src/regression.ts`. Then review a harmless-only staged change:

```bash
git commit -m "chore: dogfood bug fixtures"
# edit src/harmless.ts (comment or whitespace), then:
git add src/harmless.ts
git status --short   # only src/harmless.ts should be staged
diffowl review --staged --verbose
diffowl findings
```

**Pass when:**

- `git status --short` shows only `src/harmless.ts` staged before the review
- Previously dismissed/fixed findings stay out of backlog
- Any still-open findings remain in backlog; absence from the review did not clear them
- No old resolved findings resurrect

### 5. Markdown immutability

Pick a timestamped `review-*.md` from before lifecycle commands.

Use the checksum command for your OS before and after lifecycle commands:

```bash
# macOS
shasum -a 256 .diffowl/reviews/review-<timestamp>.md

# Linux
sha256sum .diffowl/reviews/review-<timestamp>.md
```

```powershell
Get-FileHash .diffowl/reviews/review-<timestamp>.md -Algorithm SHA256
```

```bash
# run dismiss/fix commands above if not already done, then repeat the checksum command
grep -n "## Resolution" .diffowl/reviews/review-<timestamp>.md || true
```

**Pass when:**

- SHA matches before and after lifecycle commands
- No `## Resolution` section was added

### 6. Hook persistence (non-blocking)

Commit the bug fixtures first if you have not already (see scenario 4). The hook commit should include only the harmless change:

```bash
diffowl hook install
# edit src/harmless.ts if needed, then:
git add src/harmless.ts
git status --short   # only src/harmless.ts should be staged
git commit -m "chore: hook dogfood validation"
diffowl findings
```

**Pass when:**

- `git commit` returns promptly
- Hook worker writes a new report under `.diffowl/reviews/`
- `diffowl findings` reflects persisted SQLite state

### Optional: defer command smoke test

```bash
diffowl findings defer <fnd_id> --reason "Dogfood deferral."
diffowl findings
```

**Pass when:** deferred finding disappears from unresolved backlog.

### Optional: legacy compatibility

In the DiffOwl repo (not the dogfood repo), open a pre-0.3 report fixture if available:

```bash
diffowl chat <legacy-report-path>
```

**Pass when:** legacy reports without `schema_version` still list and chat works.

## Frontmatter sanity (new reports)

New dogfood reports should include:

```yaml
diffowl:
  schema_version: 1
  review_id: rev_...
  session_id: ...
  project_root: ...
```

Finding headings should look like:

```md
#### Finding 1 (`fnd_...`) — **new**
```

## Done Criteria

**0.3 is done when:**

1. `pnpm run test` passes (includes deterministic durable-flow tests)
2. `pnpm run lint` passes
3. `pnpm dogfood:0.3` creates a usable temp repo
4. This checklist passes once on a fresh generated repo

Real LLM output is nondeterministic; keep this checklist local, not CI-blocking.
